import：借用別人已經寫好的工具箱

這一課看懂幾乎每支 script 開頭那一大串 import 在幹嘛——這也是為什麼這個專案能處理訊號、畫圖、讀圖片，卻不用自己從零寫這些功能。

跟你的目標有什麼關係 這個 repo 大量依賴別人寫好的套件（NeuroKit2、numpy、pandas、matplotlib……）。看懂 import，你才知道程式碼裡那些 np.xxx、nk.xxx 是從哪裡來的工具，而不是這個專案自己發明的東西。

2. 逐字拆解：三種 import 的樣子

寫法意思這個檔案裡的例子
import X 把整個工具箱 X 借進來，用的時候要寫 X.工具名稱。 import json → 用的時候寫 json.dumps(...)
from X import Y 只借工具箱 X 裡的其中一樣工具 Y，借來之後可以直接寫 Y，不用再寫 X.。 from pathlib import Path → 直接用 Path(...)，不用寫 pathlib.Path(...)
import X as short 把整個工具箱借進來，但幫它取一個比較短的暱稱，之後都用暱稱稱呼它。 import numpy as np → 之後都寫 np.array(...)，不寫一長串 numpy.array(...)

np（numpy）、pd（pandas）、nk（neurokit2）是這個領域幾乎公認的暱稱慣例，看到別人的程式碼也大多這樣取。

3. 用更簡單的例子鞏固

import math
print(math.sqrt(16))

from math import sqrt
print(sqrt(16))

import math as m
print(m.sqrt(16))

這三段做的是同一件事（算 16 的平方根），差別只在「怎麼稱呼」sqrt 這個工具。

動手做： cd ~/Documents/ecgtizer-neurokit2 && source ecg_env/bin/activate && python3，貼上上面三段，確認三種寫法都印出 4.0。接著試著只留 import math，直接打 sqrt(16)（不加 math.）看看會發生什麼事——這能幫你感覺到「借進來的東西到底叫什麼名字」有多重要。
